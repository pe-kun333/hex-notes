## 0. 環境と、この記録で言えること

- Chromium の browser pane（Chrome 156）。`npm run dev`（hexnote-dev、5173）と、`npm run build` の dist を hexnote-preview（4173）で開いた。
- pane は隠れたままだった（rAF 0 回／秒）。そのため rAF を 16 ms のタイマーに差し替えて回した。差し替えた回は画面のつながりにだけ使う（時刻の値は言わない）。
- 釦は DOM の click、鍵は合成の keydown・keyup で押した。本物のクリックではない。
- pane の視口の切替（1366×668 などの指定）では、隠れたページに `resize` の事象が届かなかった。S4 の canvas の大きさが前の視口のまま残ったので、`resize` を手で送って組み直した。実際のブラウザでは窓の大きさが変わると届くので、製品の直しではない（§4）。
- dev の置き場には前の手順の記録が残っていた。通しの前に `hexnote.daily` と持ち込み曲を消し、通しの後にもう一度消した（記録〔results〕は残した）。hexnote-preview は別の置き場なので、初回の端末として始まった。
- 言えない事:
  - 音の耳での確かめ。
  - 本物のクリックとキー（U-05 の手元）。
  - ヒートマップが読めるかの判定（U-05）。
  - Firefox と実機 2 台（125% を含む）。
  - 同梱曲が増えた後のデイリー（U-03・U-07 が未着で、手順 8 は未）。

## 4. 見つけた物と直し

製品の直しは無い。記録に残す物:

- pane の視口の指定は、隠れたページに `resize` を送らない。S4 の canvas が前の大きさのまま残り、ヒートマップの画素が数えられなかった。手で送ると組み直された。
- 音待ちのループは、鍵違いを押しても「ノーミス 2 周で解除」になった。待ちで当てた音は、鍵違いがあっても判定の miss にはならない（自力率の「外した」に数えるだけ。M2 の振る舞い、decisions #80）。M4 の範囲ではないので、気づきとして残す。
- 押さずに流した回からは、ヒートマップを持ち越しても空なので表示は OFF で始まる（#121 (b) のとおり）。
