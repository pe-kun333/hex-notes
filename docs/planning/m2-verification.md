# M2 通し検証の記録（M2-08、M2 の手順 10）

2026-11-01、ブランチ `claude/next-implementation-5c9639`（手順書の形では m2-10-verify）。手順は m2-kickoff.md 手順 10、完了条件は design.md §5.3 M2-08「エラーなし。持ち込み 1 曲の 4 版が S1 から通る」（decisions #78）。決定は decisions #92。

## 0. 環境と、この記録で言えること

- ブラウザ: Chromium（Claude デスクトップアプリの browser pane。Windows 11）。開発サーバー（`.claude/launch.json` の hexnote-dev。5173 が塞がっていて 5174）で開いた。S5 のフィクスチャ `tests/fixtures/smf/build.ts` は開発サーバーが配るので、build ではなく dev で通した（オフラインと更新は M1 の通しで build を見た。今回の変更は触れていない）。Firefox と実機は無い（U-05）。
- 入力は合成の keydown（`window.dispatchEvent`）。譜面の ms 表（`frameNotes`）から押す時刻を組む道具をページの中に置いた（Space の時刻 ＋ 助走 2,000 ms ＋ 着地。待ちは状態の文が「待ち」になったら次の音の鍵を押す）。AudioContext を動かすために、S2 の canvas を 1 回だけ本物のクリックで押した（合成の Space は利用者の操作に数えられず、`resumeAudio` が拒まれて S2 が同期中のまま進まない）。音は耳で聞いていない。
- browser pane の制約: 通しの途中で pane が隠れ、視口が 400×225・rAF 0 回／秒になった。M1 と同じく rAF を 16 ms のタイマーに差し替え（実際は約 35 回／秒）、視口は `resize_window` で与えた。差し替えより前に開いた画面の描画ループは、本物の rAF を待ったまま止まるので、差し替えてから読み直した。pane が隠れている間は視口を変えても `resize` が来ず、箱が前の寸法のままだったので、測る前に `resize` を送った。
- だから、この記録で**言える**のは「Chromium で持ち込み → 4 版 → 通常・練習・音ゲー向けの回 → 書き出しと取り込みが画面でつながり、記録・計測の行・箱の寸法が設計どおりで、コンソールにエラーが出ない」まで。**言えない**のは、音、実キーボード（ゴースト・IME・待ちの手触り）、Firefox、実機のフレーム落ち、OS のファイル選択とダウンロードのダイアログ。§4 に利用者の手元の表を置いた。

## 6. 出口の判定

- 「エラーなし」: Chromium の通しではエラー 0。Firefox は未。
- 「持ち込み 1 曲の 4 版が S1 から通る」: 4 版が S1 に出て、vmpk/2/octave と ableton/2/octave を S2 → S3 まで通した。上限 3 の 2 版は端末の上限が 2（未診断）なので S1 で選べない（#71 (c) の設計どおり。S6「この配列／上限の版を作る」の試験は手順 4）。
- M2-01〜07 の完了条件: 試験（tests-inventory の M2 手順 1〜9）と §1 の通しで確かめた。S5 の段 4（同期タップ）は M3-03（#79）、保存の失敗の箱は §5。
- よって M2 の出口は、§5 の手元の確かめを待つ。コードの側で残る物は無い。
