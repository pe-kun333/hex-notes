# M1 通し検証の記録（M1-14、M1 の手順 14）

2026-11-01、ブランチ `m1-14-verification`。手順は m1-kickoff.md 手順 14、完了条件は design.md §5.2 M1-14「エラーなし。初回導線 5 分以内」。決定は decisions #77。

## 0. 環境と、この記録で言えること

- ブラウザ: Chromium 152（Claude デスクトップアプリの browser pane。Windows 11、devicePixelRatio 2）。build を `vite preview`（`.claude/launch.json` の hexnote-preview、4173）で開いた。Firefox と実機 2 台は無い（U-05）。
- 入力は合成の keydown（`window.dispatchEvent`）。音を鳴らす釦（S0c の音のテスト・「聞こえる」・S0a の決定・S0b の次へ・「更新する」）は本物のクリックで押した。音は耳で聞いていない。
- browser pane の制約: Claude の窓が前に無いと rAF が止まるか 1 秒に 2 回ほどに間引かれ、ページが hidden になると S2 は設計どおり一時停止する（focus.ts）。通しの途中から rAF を 16 ms のタイマーに差し替えた（時計は performance.now なので判定の時刻は変わらない。フレーム間隔の計測は差し替えの値になる）。
- だから、この記録で**言える**のは「Chromium で画面がつながり、箱の寸法・保存・計測の行・オフライン・更新が設計どおり動き、コンソールにエラーが出ない」まで。**言えない**のは、手の速さ（初回導線の秒）、音、実キーボード（ゴースト・IME）、Firefox、実機のフレーム落ち。§4 に利用者の手元の表を置いた。

## 2. 初回導線（S0a → S0d）と計測の行

上の環境で S0a から S0d の段階 3 まで通し、S3 に「初回導線はここで終わります」が出た。IndexedDB の telemetry に残った行:

| 行 | 中身 |
|---|---|
| onboard S0a | 47.4 秒、left 偽 |
| device | chrome/windows・1440×960・dpr 2・上限 4・getLayoutMap 可（tsResolution なし） |
| onboard S0b | 23.4 秒（10 組とも合成で通過 → 上限 4。実機の値ではない、U-04） |
| calib tap | n 24・SD 4.2・適用・−120（平均 ＋129 ms を ±120 で切った。§3 の F3） |
| onboard S0c | 46.5 秒 |
| play ×3（S0d の段階 1〜3） | 100%・UR 55.7／100%・UR 68.1／94.4%・UR 528.5、入力遅延の中央値 0〜0.05 ms（合成の打鍵なので timeStamp ≈ now）、pressNoLag 0、audioLateMaxMs 0、フレーム SD・p95 は段階 1 が null（rAF が止まり 1,000 ms 超の間隔を除いた）、段階 2・3 は p95 33 ms（タイマーに差し替えた値） |
| onboard S0d | 261.9 秒 |
| calib propose | n 16・SD 52.8・reason sd（提案なし） |

- 秒の和は 379.2 秒で 300 を超えたが、主担当の道具の往復と、S0d の段階 1 の間 rAF が止まっていた分を含むので、利用者の所要秒ではない。下限の見積もり: S0d は 3 段階 ×（助走 2 s ＋ 曲 32 s ＋ 余韻 1.2 s）＝ 105.6 s、S0b は 10 組 × 保持 1 s 強 ≒ 15 s、S0c は予備 4 拍 ＋ 24 打 × 0.6 s ≒ 17 s で、読む時間を除いて約 140 s。**5 分以内かは実際の手で測る**（§4。M-4）。
- 書き出し（計測盤）は手順 12 で中身を見た。実際のダウンロードは押していない（§4）。

## 3. 見つけた物と直し

| id | 重さ | 見つけた物 | 直し |
|---|---|---|---|
| F1 | high | **初めて開いた回に新しい版が出ると「更新する」が効かない。** そのページは SW の制御下に無く、新しい SW は待たずに有効になる（前の SW が制御するページが無いので）。workbox は needRefresh を知らせるが、skipWaiting を送る先が無く、`controlling` も来ないので読み直さない | `sw-register.ts` の apply: 待っている SW があり、ページが制御下のときだけ skipWaiting、それ以外は `location.reload()`（読み直せば新しい版）。browser pane で 2 つの道を確かめた: (A) SW を消して開き直した回（controller なし・待ちなし）→ S6 の「更新する」で読み直し、制御下に。(B) その後に版を上げた回（制御下・待ちあり）→ 読み直し、待ちが消えた。S3 の「更新する」の行が出ることも見た（押したのは F1 の直しの前で、読み直さなかった） |
| F2 | mid | **オフセットがもう上限（−120 ms）のとき、S3 が「平均 ＋22 ms → オフセットを −120 ms にしますか」と、今と同じ値を提案した**（きらきら星・歓喜の歌の両方）。提案 ＝ 使った − 平均 を ±120 で切ると、使った値に戻る | `proposeOffset`: 切った提案が今のオフセットと同じなら提案しない（reason small。変える量 0）。試験で通しの値（使った −120・平均 ＋22・ヒット 42）を再現した。画面での再確認はページが hidden になって S2 が進まず、できていない |
| F3 | low | 段 1 で平均 ＋129 ms のとき「オフセットを −120 ms にしました」とだけ出て、残る 9 ms の遅れが読めない | 上限で切ったときだけ段 1 と段 2 の文に「（上限 ±120 ms。それより大きいずれは残ります）」を足した（ちょうど ±120 は足さない） |
| F4 | 記録 | rAF が間引かれた間に低負荷の帯が上がり、そのまま（自動では戻さない、decisions #29 (c)） | 直さない（pane の環境の影響）。実機のフレーム落ちは M-7 で見る |

## 5. 出口の判定

- 「エラーなし」: Chromium の通しではエラー 0。Firefox は未。
- 「初回導線 5 分以内」: 未判定（手の速さで測る）。下限の見積もりは約 140 秒。
- 同梱曲は U-03 の代わりの 3 曲のまま（m1-kickoff §5。9 曲は利用者の手元作業）。
- よって M1 の出口は、§4 の手元の確かめと U-03・U-04・U-05 を待つ。コードの側で残る物は無い。
