# 先出し案 R1（主担当の素案。調査結果や検討担当の案を見る前に書いたもの）

書いた日: 2026-10-23

## 0. 前提の読み直し：「六角セル」と「キーボード鍵盤」は一体にできる

- 企画は「六角セルの音符」と「PC キーボードを鍵盤に見立てる」という 2 つの見立てを持つが、
  PC キーボードの文字キーは行ごとに横へずれた千鳥配列であり、これはほぼ六角格子（pointy-top・行オフセット）と同じ形をしている。
  - 一般的な QWERTY では Q 行→A 行のずれが約 1/4 キー、A 行→Z 行のずれが約 1/2 キー。六角格子は行ごとに 1/2 ずれなので、A→Z はそのまま、Q→A は近似。
- つまり画面下の「鍵盤」をキーボードそのものの形（千鳥に並んだ六角セル）で描けば、上から来る六角セルは「下の同じ形の場所へ落ちる」ことになり、
  視線の対応が最も素直になる（レーンの文字を読む→鍵盤の文字を探す、という二度手間が消える）。
- 六角格子は各セルが 6 近傍を持つので、「隣のキー＝近い音程」という等方性配列（Wicki-Hayden など）をそのまま載せられる。
  これは「六角セル」を飾りではなく意味のあるものにする筋。

## 1. 核となる方式の候補

- A. レーン落下型（1 キー＝1 レーン）: 標準的。六角セルは各レーンの中を落ちる。行（Q 行/A 行/Z 行）をまたぐノートを見失いやすい → 行ごとの色分け、レーンの高さ違いで補う。
- B. ハニカム落下型（キーボードの形をした着地面）: 上から来る六角セルが、下部のキーボード形ハニカムの「同じ列の位置」に着地。着地点のセルが事前に光る（予告）。本命候補。
- C. 等方性配列（Wicki-Hayden / Harmonic Table）で「方向＝音程」: メロディが六角格子上の経路として見える。初心者には難しいが、楽器として深い。上級者モードまたは別プリセット。
- D. ピアノ鍵盤見立て（DAW 慣例: Z 行＝白鍵、S D G H J＝黒鍵、Q 行＝上のオクターブ）: ピアノを学びたい層向け。実鍵盤（MIDI）へ移行しやすい。
- E. 「来る」のではなく「照らす」: ノートが落ちず、キーボード形の盤面上で次に押すキーが順に光る（タイピングゲーム／Simon 風）。チュートリアルや練習モードに。落下と併用のハイブリッドもあり。
- F. 収束・放射型: 中央の鍵盤へ向かって六角セルが集まる。見栄え重視だが読みづらいおそれ。
- G. 経路型: ノート同士を線で結び、手の移動の道筋を見せる（osu! のフォローポイントに近い）。B や C と組み合わせられる。
- H. 反転: 鍵盤から湧き上がる／鍵盤を上に置いてノートが上昇。新規性はあるが慣例に反する。

→ 直感では「B + D」を初心者の標準、「B + C」を上級者向け、「E」をチュートリアルと練習に使う組み合わせ。

## 2. 入力とマッピング

- 物理キー基準（KeyboardEvent.code）で判定し、JIS/US 配列の違いに依存しない。表示する文字は現在の配列から取る（navigator.keyboard.getLayoutMap が使えるブラウザでは自動、それ以外は手動選択）。
- 配列プリセット: ピアノ風 2 段／Wicki-Hayden／Harmonic Table／「位置優先」（音程と無関係に、手の移動が小さくなるようにキーを割り当てる）。
- オクターブ・移調のシフトは大きなキー（Shift / Space / Tab）に置く。
- 同時押し上限の問題: 設定画面に「同時押しテスト」を置き、押せる数を測って譜面の同時押し数上限に反映する。
- 運指最適化: 「位置優先」モードでは、採譜結果→キー割り当ての段階で手の移動量と同時押しの指の届く範囲を評価して割り当てる。

## 3. 譜面生成パイプライン

- 入力の 3 経路: (a) MIDI ファイル持ち込み、(b) ローカル音源からブラウザ内で自動採譜、(c) コミュニティ譜面（YouTube ID + 譜面データのみ共有、音源は含めない）。
- YouTube は「再生」にだけ使う（埋め込みプレイヤー）。音声データは取れない前提。
- 工程: 音源分離（ボーカル／ピアノ／伴奏）→ 採譜 → 主旋律抽出 → 量子化 → 難易度別の間引き（密度・同時押し・跳躍・速さの上限）→ キー割り当て → 検証（自動プレイで通せるか、運指が成立するか）。
- 難易度は 1 つの数字ではなく「密度／同時押し／跳躍／速さ」の 4 軸で見せる。

## 4. 判定・スコア・音

- 判定幅は 3〜4 段階（例: ±25 / ±60 / ±110 ms）。設定で甘くできる。
- オフセット校正（メトロノームに合わせて叩く／自動）。
- 押したキーの音（ピアノ音源）を必ず鳴らす。ミスは音を鳴らさないか濁らせる。「自分が演奏している」感覚が核。
- ロングノートは六角セルが縦に連なる帯。同時押しは横に並んだセルを薄い線で結ぶ。

## 5. 学習・練習（ピアノ学習への橋渡し）

- 段階的な足場外し: 文字＋音名＋色 → 文字のみ → 無表示（譜面を覚える）。
- 待ちモード（正しいキーまで止まる）、区間ループ、スロー、片手、ミラー。
- ミス分析（どのキー・跳躍・同時押しで落ちるか）→ 苦手だけを集めた練習譜面を自動生成。
- MIDI 鍵盤対応: 同じ譜面で実鍵盤でも遊べる。PC キーボードは入口、実鍵盤が出口。
- 耳コピモード: ノートを隠す／遅らせて見せる。

## 6. 追加機能・システム

- 譜面エディタ（自動採譜の手直し、YouTube 同期のオフセット調整、難易度の間引き調整）。
- コミュニティ: 譜面共有、ランキング、リプレイ、ゴースト対戦。
- 配信連携: 視聴者が次の曲をリクエスト、オーバーレイ表示。
- 自由演奏モード: 譜面なしで鍵盤だけ（練習・作曲）。録音して譜面化。
- 和音を六角のクラスタとして見せる（Harmonic Table なら三和音が三角形になる）。
- 歌詞・コード名の表示。
- スキン・テーマ、色覚多様性に配慮した配色。
- オフライン対応（PWA）、デスクトップ化（Tauri）。

## 7. リスク・疑問

- 六角セルの文字が小さくて読めない（セルの大きさと落下速度のトレードオフ）。
- 行をまたぐノートの視線移動。
- 自動採譜の誤りで「遊べない譜面」になる。
- YouTube 規約（プレイヤーの上に重ねて描けない、広告を隠せない）と音ズレ。
- メンブレンキーボードの同時押し制限。
- JIS 配列の記号キーの位置差、IME の干渉。

## 8. モックの候補

- M1 コア: 六角セル落下 ＋ キーボード形鍵盤 ＋ 判定 ＋ ピアノ音（内蔵の簡単な曲）。
- M2 配列エクスプローラ: ピアノ風／Wicki-Hayden／Harmonic Table をキーボード形で可視化し、押すと音が鳴る。
- M3 パイプライン: YouTube 同期 ＋ 譜面オフセット校正、または採譜→難易度間引きのデモ。
- M4 設定・練習: 校正、同時押しテスト、足場外しの段階デモ。
