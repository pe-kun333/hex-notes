読み方:
- 〔導〕と〔例〕だけで並べても、読みやすさ・橋渡し・縦予算が揃うのは「B 段別着地＋D-1 か D-2」で、G 辺ヒントはその補助、E は縦予算の対照として残す。先出しの直感「B+D 標準、B+C 上級、E チュートリアル」とは一致するが、〔推〕のセル（B の読みやすさ、黒鍵に見えるか、A–Q 継ぎ目、E の輪の重なり、同時押し列の全部）は m0／m1'／m2／input-05 で埋めるまで判定の根拠にしない。
- 「和音の見せ方」で塊になるのは隣接セルの和音か等方性配列（C）のときだけ。ピアノ型（D-1／D-2）では三和音は殻で描かれるので、六角の隣接に音楽的意味を持たせるか（問い 0'）を先に決める。

## 3. モック仕様

共通:
- 単一 HTML（Canvas 2D／Web Audio 合成音、外部音源なし）。ファイル単体で開いても動く。
- 譜面は m5 が出す JSON（pipeline-03 三層: 音符／拍パルス／同期）を共通形式とし、内蔵 6 曲も同じ形式の JSON を埋め込む。m1'／m4 はこの JSON を読む（内蔵曲依存を外す）。
- 同時押し上限の既定は 2。3 以上は input-05 の診断を通過した端末だけ。譜面は上限ごとに間引いた版を持つ（m5）。
- 時計（ダミー動画時計・補間）は m3 だけが扱う。他のモックは performance.now() の単一時計で動く。
- プレイヤー矩形は実寸の灰矩形（前に何も置かない）で表す。

### m0 レイアウトと縦予算
- name: m0-layout
- purpose: 1366×768 のノート PC 画面で、プレイヤー 480×270（最小 200×200）・落下域・4 段鍵盤図が同居する配置を実寸で見る。far-16（固定セル・リング収縮）を落下域なしの対照として置く。
- shows: 3 配置（左右分割／上下／鍵盤図を落下域の床に兼用）を切り替え、プレイヤーは実寸の灰矩形。内蔵曲 1 曲の自動再生で落下セル、または far-16 の収縮する輪が動く。落下域の有効高さ（判定線まで何秒分か）、段別着地の押し上げ量（段数×セル高）、セル寸法と文字の px を数値で表示。
- interactions: 配置切替、仮想画面枠（1366×768／1280×720／1920×1080）、プレイヤー寸法（480×270〜200×200）、鍵盤図の段数 2／4、落下域方式（落下／far-16）、セル寸法 24／26／28 px、ハイスピード倍率。
- done_when: 768 px 高で 3 配置それぞれの落下域の有効秒数（ハイスピード 1.0 で判定線まで）とセル寸法が数値で出て、成立する配置（有効 1.5 秒以上・セル 24 px 以上）が分かる。far-16 を残すかを主担当が決められる。

## 7. 反論への応答

判定は 受入／一部受入 の二つ。どの反論も根拠が catalog の記述と m1 の実装にあり、全面的に退けるものは無かった。一部受入は、採らなかった部分の理由を書く。

1. 「すぐ」13 項目は一つの設計変更（high）— 受入。「すぐ」を m1 の切替だけで足せる 5 件＋準備作業 2 件に絞り、幾何を変える core-01／critic-01／critic-02／core-06／tech-04／critic-03 は m1' 幾何一括に括った。数字段は 26→24 px で止めた。learning-05 の分母未定義は m4 に送った。

2. 六角は見た目か意味か（high）— 受入。問い 0' を立てた。m1' の done_when を「既定配列で塊が発生する和音の割合（譜面統計）」と「塊が出ないときの殻で同時性が読めるか」に分け、core-03 を上級プリセットでなく「対照条件」として m1' に固定プリセットで入れた。social-13 の実績・隣接連鎖は問い 0' の答えが「意味」のときだけ「次」に残る、と条件を付けた。

3. 比較表の根拠（high）— 受入。各セルに〔実〕〔例〕〔導〕〔推〕を付け、〔推〕は記号を外して測るモックを書いた。新規性を外し、時計・同時押し・縦予算の 3 列を足した。G 経路型の読みやすさは ◎ から ○ に下げ「B の補助に限る」と明記。A の 75% は六角格子の 50% に直し、物理換算を括弧に残した。「実装の手間 小」は core-01 との同時決定が要る旨を書いて「m1' 一括」とした。

4. 譜面パイプラインのモックが無い（high）— 一部受入。問い 0（主経路と対象層）を復活させ、m5 曲の持ち込みを m2 と同格に置き、m1'／m4 は m5 の JSON を読む形にした。採らなかった部分: 「初回プレイ前に 30〜60 秒タップさせる離脱率」は利用者テスト無しのモックでは測れないので、m5 では「かかった時間と残差」を記録するに留め、離脱は a-03 初回導線（「次」）で記録する設計にした。問い 9 で「初回に同期タップを出すか」を主担当に聞く。

5. 同時押し診断の順序（high）— 受入。input-05 の最小形を m1' の冒頭（tech-04 より前）に置き、既定の同時押し上限を 2、3 以上は診断通過時のみとした。譜面側は m5 の pipeline-04 で上限ごとに間引いた版を出す。問い 7 を足した。

6. ダミー時計の自己充足（mid）— 一部受入。時計は m3 だけが扱い、m1' からは外した。m3 の本線を実 IFrame（自前の限定公開クリック動画）にし、done_when を「実動画で残差 SD と UR が出る（Chromium と Firefox）」に変えた。採らなかった部分: ダミーを「予備」に落としつつも画面から外さない。共通の約束「ファイル単体で開いても動く」を保つためで、file:// では IFrame API が動かないことがある。また自前の限定公開動画には広告が出ないので、広告は a-01 として模擬（人工の飛び）で確かめ、実測は製品の動画に送る。動画のアップロードは主担当が自分で行う作業として前提に書いた。

7. 段ずれの前提分布（mid）— 受入。「すぐ 7」に手元実機の計測を置き、m2 に段ずれ自己申告 UI と「正六角のまま文字だけで押す」退避を足した。m2 の done_when に「実機 2 台以上で黒鍵位相の合否が見える」を入れ、問い 2 に (d) 退避を足して「m2 で比べてから」とした。

8. 成績連動透明度の二重（low）— 受入。「すぐ」は m1 既存の手動ラベル段階だけに留め、成績連動と自力率の分母は m4 に一本化した。m4 の shows に分母の 4 区分を明示し、問い 6 は m4 の done_when で答える形にした。Hsieh 2026 が VR 運指手本で刺激が違う点は catalog の根拠として弱いと認め、m4 の実測を根拠にする。

9. レイアウトのモックが無い（mid）— 一部受入。採った部分: プレイヤー矩形を実寸で置いた 3 配置と far-16 の表示切替、768 px 高での成否を done_when に入れた。採らなかった部分: m1' に足すのではなく m0 として別のモックにした。反論 10 が m1' の切替の増殖を戒めており、レイアウトは幾何（配列・着地・黒鍵）とは独立の変数なので、別に切り出した方が「一度に変える変数は 1〜2」を守れる。m0 は自動再生で動くので、落下域と far-16 の見え方は比べられる。

10. m1' の切替の海（mid）— 受入。「既定（ピアノ入門者）」「音ゲー向け」の 2 プロファイルに固定し、切替は着地方式・黒鍵見立て・辺ヒントの 3 つだけに残し、他は設定画面に退避した。音ゲー向けにはハイスピード倍率・FAST/SLOW・精度%／ランク／ゲージを、入門者向けには音名表示・緩い判定窓・NEAR を既定にした。黒鍵見立ての選択肢に W–H 対照を含めたのは反論 2 のため。

11. pipeline-06／tech-08 の見送り（low）— 受入。見送りから「保留」に移し、「すぐ 6」の準備作業として COEP 2 種×YouTube iframe の読込可否を確認して記録する。結果で見送りを確定するか「後」「次」に戻す。

不足 5 件:

- スコア式とクリア条件 — a-02 として m1' の音ゲープロファイルに入れ、譜面版（配列＋上限）ごとの別集計で比較可能性を決めた。問い 8。
