# ADR 0006: 段別着地が「位置で読めるか」の確かめ方

日付: 2026-10-30。状態: 採用（方法）。結果は利用者の手弾きの後に本 ADR へ書き足す（kickoff §7-25）。

## 文脈

decisions #3 は段別着地（セルが自分の鍵に重なった瞬間が押し時）を既定、一本線を対照にした。design.md §5.7 は「段別着地が位置で読めるか」を M0-03b の途中で確かめ、読めなければ一本線を既定に戻す提案を出すとする（やり直し最大 6 日、kickoff §7-2）。相談 B は計算で、1 段ぶんの着地の y 差 1.5·R ＝ 42 px を流速で割った「逆転の窓」が 668 で 140 ms、514 で 210 ms と出し、6 曲×2 配列で逆転の組は scale×vmpk の 1 件だけ、試されるのは段またぎ和音の同時性と半音階の Q↔A 交互だとした。読めるかは人が弾かないと分からない（1 人・1 回）。

## 決定

- 道具: 開発ページ `src/app/dev/play.html`（vite dev のときだけ index から導線）。曲 6 本（tests/fixtures/charts/m1/ の ableton/2/octave・vmpk/2/octave）と負荷譜面（60〜76 の半音階を上下、3.5 音/秒・20 秒。ableton で Q↔A、vmpk で数字↔Q が交互）、着地は段別と一本線を切り替える。入門者の 1.5 s、辺ヒントあり、文字 both が既定。
- 記録: keydown を着地 ±300 ms の未対応の音に対応付ける（同じ鍵で最も近い音、無ければ最も近い音を鍵違い）。走りごとに外し率（±300 ms に keydown が無い＋鍵違い）・正しい鍵の dt（押した − 着地）の標本標準偏差（全体・段ごと）・入れ違い（正しく押した音を和音ごとにまとめ、着地の順に隣り合う和音で「前の和音の押した時刻の最大 ＞ 次の和音の最小」になった回数。和音の中の並びに依らない）・和音の押した時刻の幅の中央値を出し、利用者が「未記入／読めた／読めない」を選ぶ（未記入は主観の数に入れない）。フレームは ±300 ms＋50 ms の余裕を過ぎた音を取り逃しにし、その後に届いた窓の中の押下は記録だけして返しを出さない。ページの JSON（走りごとの集計と音ごとの [添字, 鍵, 段, 着地 ms, 押した ms, 押した鍵]）を写して渡す。
- 手順（推奨）: 1366×768 相当の視口で、12 本を段別 → 一本線の順に弾く。半音階・音階・負荷譜面は内側の高さ 514 前後の視口でも弾く。
- 判断（相談 B の目安、仮）: 次の 5 観点のうち 2 つ以上を満たしたら「読めない」とし、本 ADR に数値を付けて一本線を既定に戻す提案を書き、`src/render/hex/landing.ts` の DEFAULT_LANDING を `line` にする。1 人・1 回なので主観を優先してよい。

| 観点 | 指標 | 一本線へ戻す目安 |
|---|---|---|
| 鍵の同定 | 外し率 | 段別が一本線より 5 ポイント超悪い |
| 時刻の同定 | dt の SD（全体・段ごと） | 段別 SD が一本線 +20 ms 超、または上段 SD が最下段 +30 ms 超 |
| 順序 | 入れ違い回数 | 段別が一本線より多い（負荷譜面） |
| 同時性 | 和音の押した時刻の幅の中央値 | 段別が一本線 +30 ms 超 |
| 主観 | 読めない本数（12 本中） | 3 本以上 |

## 帰結

- 開発ページの判定は開発用の仮（入門者の窓 24/100/180・遅れ側 ×1.3 で判定文字と縁の返しを出す）。製品の判定層は手順 8。
- 結果が出るまで既定は段別（cell）のまま。戻すと決めたら、スナップショット 12 本（decisions #28）は段別のまま残し、一本線の 12 本を足すかを手順 6 の PR で決める。
- 主担当は Claude の browser pane で描画と操作だけを確かめた（pane が隠れると rAF が間引かれるので、読めるかの判断には使わない）。
